## 一、结论

**直接在原代码上加功能，不重写。** Python 和侧车之间的连接、认证、进程管理、自动安装这些都可以保留。

需要说明一点：两边之间的「传话规则」现在只有一种发送指令，而且只能带文字和附件，发出去以后也拿不到回音。所以要给它**加**东西：给每个请求编个号、让侧车回报结果，再加点赞、输入中这些新的指令类型。原来的指令照常能用。按任务书的说法，这属于「扩展」，不是「重做传话层」。

按任务书，审计完可以直接开工。但有一项依赖变更超出了任务书的授权范围（见第六节第 1 条），需要你点头。

## 二、最要紧的 6 个发现

| # | 发现 | 对你意味着什么 |
|---|---|---|
| 1 | **普通 iPhone 照片很可能被拦掉了。** 代码把所有 HEIC 格式的图片都当成「实况图」丢弃。iPhone 相机默认用的就是 HEIC（「高效」格式），并不只实况图才是。 | 你发的大多数照片，AI 可能根本没看到。第 2 步做 HEIC 转 JPEG 时会修好。 |
| 2 | **两类消息会被整条丢掉：** ① 你在 iMessage 里长按 AI 的某句话、选「回复」后发的消息；② 文字和照片一起发，或一次发多张照片。Photon 把这两种分别标成「回复」「组合」类型，现在的代码不认识，直接丢了。 | 这是现有的 bug，不是新功能。建议放进第 2 步一起修。 |
| 3 | **fnOS 不保留可执行权限，会影响两件事：** ① 自动安装的 Node 程序本身；② 现在锁定的 TypeScript 7 编译器。TypeScript 7 不是脚本，而是一个必须有「可执行」标记的原生程序。任务书建议的写法 `node …/tsc` 对它不起作用，我读了它的启动代码确认过。 | 需要把 TypeScript 换回 5.9 版（纯脚本，参考材料用的就是这一版），Node 也要换个启动方式。**换 TypeScript 需要你同意。** |
| 4 | **大图片可能让侧车崩溃。** 图片转成文本后体积会多出约三分之一，现在的上限是 10MB，所以大约 7.5MB 以上的照片就会超限，连接被切断，侧车跟着重启。 | 违反「失败不影响聊天」。第 1 步修：超限的图片先压缩，压缩后还超限就跳过，并告诉 AI。 |
| 5 | **发消息是「交出去就算成功」。** Python 不等侧车回音就告诉 MaiBot 发送成功，MaiBot 也拿不到这条消息在 iMessage 里的编号。 | 引用、撤回、编辑、点赞都要靠这个编号，所以这是第 1 步必须补上的「回执」。补上以后，MaiBot 会自动把自己的消息记录换成 iMessage 编号，这一点已经在 MaiBot 源码里确认。 |
| 6 | **任务书里有一条判断，实际情况相反。** 任务书第 11 节说「对方引用了哪一句会被压平成纯文字」。我读了锁定版本和最新版本的源码：两个版本都会**保留**被引用的那条消息。 | 「对方引用了哪一句」从「做不了」改成「可以做」，还要真机确认。 |

## 三、逐题回答（任务书第 4 节 1–10）

### 1. 一条消息怎么走

**收消息：** 你的 iPhone → Apple → Photon 云端 → **侧车**（树莓派上的 Node 小程序，用 spectrum-ts 一直在「听」新消息）。侧车把消息翻译成简单的文本格式，图片转成一长串字符，再通过本机内部连接（127.0.0.1:18763，外网看不到）交给 **Python 插件**。插件把它换成 MaiBot 认识的格式，交给 MaiBot。

**回消息：** MaiBot 想好回复后，调用插件的发送入口，把一份「消息字典」交给它。插件从里面取出文字和图片，发一条 `send` 指令给侧车，侧车再通过 Photon 发到你的 iPhone。

**问题：** 插件把指令交给侧车就立刻告诉 MaiBot「成功」。侧车真的发失败了，只会在日志里记一笔，MaiBot 和 AI 都不知道。

### 2. 两边之间现在有哪几种消息

| 方向 | 类型 |
|---|---|
| 侧车 → Python | `auth`（认证）、`ready`（Photon 就绪）、`message`（收到消息）、`error`（出错）。Python 也认 `status`，但侧车从来不发。 |
| Python → 侧车 | `auth_ok`、`send`（只能带文字和附件）、`shutdown` |

**能不能装下点赞、输入中、引用、编辑、撤回？** 底层连接装得下，它传的是通用格式，加新类型很容易。现在的规则装不下，缺三样：
- **请求编号和回执**：发出去的东西没法和结果对上。
- **消息句柄**：侧车不保存发过、收过的消息对象，而点赞、引用、撤回、编辑都要拿着原消息对象才能做。
- **入站类型**：侧车只转发文字和附件，点赞、已读、回复、组合、名片、投票都在侧车那一层就被丢了。

这三样都可以在原连接上**补**，不用推倒。

### 3. spectrum-ts 版本，要不要升级

- **现在：** `package.json` 写的是 `^8.2.1`，意思是「8.x 里 8.2.1 以上都行」，没有锁死。实际锁定文件里装的是 **8.2.2**（2026-07-06）。
- **最新：** **12.10.1**（2026-09-23），和 AstrBot 参考材料用的是同一版。

我把两个版本都装下来，对照了它们的类型声明：

| 对比项 | 8.2.2（现在） | 12.10.1（最新） |
|---|---|---|
| 点赞、引用、输入中、发已读、编辑、撤回、特效、投票、背景、名片分享、发语音、富链接、按编号取附件 | 都有 | 都有 |
| **对方已读**（入站已读回执） | **没有**，收到也不转出来 | 有 |
| 语音识别成「语音」类型 | 不会，当成普通附件 | 会，还会把 .caf 标成正确的音频格式 |
| 附件详情（传输状态、是不是实况图的视频部分） | 没有 | 有，对排查语音下载失败有用 |
| 依赖数量和体积 | 约 189 个包、167MB，含一个要现场编译的数据库模块（Mac 本地模式才用，我们用不上） | 只装 core 和 imessage 两个包：约 105 个运行时包，没有要现场编译的模块 |
| 改代码的工作量 | — | 我实测过：现有侧车代码只改 2 行引用路径，就能在 12.10.1 上通过类型检查 |

**建议升级到 12.10.1，并锁死精确版本。** 理由：第 4 步的「对方已读」只有新版才有；语音接收新版更好排查；依赖更轻，在树莓派上更安全；参考材料里记录的坑也都是基于这一版。

### 4. MaiBot 插件 SDK 的版本，新旧写法是否一致

- MaiBot 最新版是 **1.3.5**（2026-10-07）。官方镜像按锁定文件安装插件 SDK **2.10.0**。PyPI 上最新是 2.11.0，但镜像不会用它。
- 适配器用的是**新写法** `@MessageGateway(route_type="duplex")` 和 `ctx.gateway`，和 SDK 2.10.0 一致。插件声明支持 SDK 1.0–2.99、MaiBot 1.0–1.99，没有冲突。
- 我在 SDK 2.10.0 里确认过，后面要用的接口都在：@Tool、@EventHandler（含 ON_PLAN、POST_SEND、AFTER_SEND）、@HookHandler、`ctx.maisaka.context.append`、`ctx.llm.transcribe_audio`、`ctx.send.custom`。
- 树莓派重装后实际装的版本，要在本地会话里查一次（命令见第七节）。

### 5. 出站消息字典长什么样（最小实验）

**做法：** 云端从 PyPI 装了 SDK 2.10.0，并装了 MaiBot 1.3.5 的源码和依赖，直接运行 MaiBot 里负责「把消息交给插件」的那段真实代码。

| 情况 | 插件实际收到的 | 结论 |
|---|---|---|
| 引用回复 | `{"type":"reply","data":{"target_message_id":"…", …}}`，排在最前面 | **原样到达** |
| 语音 | `{"type":"voice","hash":"…","binary_data_base64":"…"}` | **原样到达** |
| `ctx.send.custom("imessage_effect", {...})` | `{"type":"dict","data":{"type":"imessage_effect","data":{...}}}` | **内容原样到达，但外面多包了一层 `dict`**，适配器要拆开这层。另外，如果自定义类型恰好叫 text、image、voice、reply 等，会被转成标准消息段。 |
| 你发来的消息的编号 | 保留为 Photon 的消息编号，MaiBot 用它去重 | 好消息：引用回复时，目标编号就是 iMessage 的真实编号 |
| 插件回报发出消息的编号 | MaiBot 会把自己记录里的编号**换成**这个编号 | 好消息：补上回执以后，AI 看到的历史里就有真实编号，撤回、编辑可以直接用 |

另外，MaiBot 自带的回复工具已经有一个「要不要引用」的参数 `set_quote`，由 AI 自己决定。「引用回复」三档里的「AI 自己决定」可以直接用它。

**局限：** 这个实验跑的是 MaiBot 的转换代码，不是一个完整运行、接了插件进程的 MaiBot。完整链路要靠真机验证。

### 6. 拦语音、HEIC、名片的代码在哪；按编号取附件能不能绕开

位置都在侧车 `sidecar/src/index.ts`：
- 第 149–156 行：.caf 或音频附件，跳过
- 第 158–165 行：HEIC/HEIF，跳过
- 第 181–186 行：语音类型，跳过
- 第 187–192 行：其他所有类型（名片、回复、组合、点赞、已读、投票……），跳过
- 出站语音：`plugin.py` 第 732–734 行，侧车第 291–294 行

**名片：** README 说「只作为元信息接收」，实际情况更糟。Photon 已经把名片解析成「联系人」类型，正好落进第 187 行的「其他」，**整条丢掉**。

**按编号取附件能不能绕开语音问题：** 恐怕不行。我读了两个版本的源码，`getAttachment(编号)` 内部调用的下载函数，和正常收消息时用的**是同一个**。服务器那边的下载本身坏了的话，换个入口没用。

有一种情况能救：语音还没上传完我们就去下载了，所以失败。12.10.1 能看到附件的「传输状态」，可以等它传完再重试几次。参考材料里没有关于这个 UNAVAILABLE 错误的记录（我搜过）。

**计划：** 第 4 步按「看传输状态 → 等一等 → 用编号重试 → 还不行就得体地拒绝」来做，结果以真机为准。

### 7. 普通照片会不会被 HEIC 规则误拦

**很可能会，而且是大部分照片。** iPhone 相机默认的「高效」格式存的就是 HEIC，iMessage 在苹果设备之间通常原样发送。代码注释把 HEIC 叫「实况图片」，这是误解。

Photon 实际送来什么格式，云端看不到。第 1 步会在日志里记下每个附件的格式和文件名，你发一张照片就能确认。

**顺带发现：** 除了音频和 HEIC，侧车把**所有附件**都标成「图片」，包括 PDF 和视频，MaiBot 会拿 PDF 当图片去看。第 2 步一起改。

**HEIC 转 JPEG 的方案：** 在 Python 这边用 pillow-heif。它有现成的树莓派（ARM64）版本，6.4MB，不用现场编译。MaiBot 镜像里已经带了它要配合的 Pillow 12.3。

### 8. 树莓派的资源占用和 ARM64 兼容性

- **Node 从哪来：** 官方镜像（python:3.13-slim）里没有 Node，所以插件会用 nodeenv 自动下载。下载约 30MB，解压后 100MB 多一点。
- **侧车依赖：** 现在 167MB。升级后按上面的方案约 100MB，加上 TypeScript 5.9 再多 23MB，全是纯脚本，ARM64 没有兼容问题。现在的依赖里有两样要特殊处理：TypeScript 7 的原生编译器，和一个可选的数据库模块（在精简镜像里编译不了，会白白浪费时间）。
- **内存：** 只加载 SDK 就占约 100MB（在云端 x86 上实测）。估计在树莓派上运行时 120–200MB，4GB 内存够用。
- **耗时风险：** 代码里写死了 `npm install` 最多 120 秒、编译最多 60 秒。树莓派的存储比较慢，首次安装可能超时，然后失败。建议放宽到 600 秒和 300 秒。编译在云端只要 2 秒左右，在树莓派上估计 10–30 秒。
- **没法在云端验证的：** 真实安装耗时、峰值内存、连续运行一天的内存曲线。这些放进真机验收清单。

### 9. fnOS 权限位

| 环节 | 现状 | 能否运行 | 改法 |
|---|---|---|---|
| Node 程序 `.nodeenv/bin/node` | 装在插件目录（在 /vol1 上） | **很可能不能**：所有权限位都是 0 时，连 root 也执行不了程序 | 每次启动时，把 node 复制到容器自己的临时目录，加上可执行标记再用。约 1 秒，**不用改 Docker 配置** |
| `npm install` | 调用 `.nodeenv/bin/npm` 脚本 | 不能 | 改成 `node …/npm-cli.js install`，参考材料就是这么做的 |
| 编译 `npx tsc` | npx 是脚本；TypeScript 7 还会再去启动一个原生程序 | 不能，任务书建议的 `node …/tsc` 对 TypeScript 7 也不行 | **把 TypeScript 换回 5.9.3**，用 `node node_modules/typescript/lib/tsc.js` 编译（需要你同意） |
| 依赖的安装脚本 | 只有 protobufjs 一个，内容是「用 node 跑一个脚本」 | 可以，只要 node 本身能运行 | 让它用上面复制出来的 node |
| 启动侧车 | 已经是 `node dist/index.js` | 可以 | 不用改 |
| 「工作区必须干净」之类的检查 | 安装器里**没有** | — | 不用改。树莓派上的 git 建议设一次 `core.fileMode false`，`git status` 就不会再显示假的 M |

还要真机确认：在容器里看，插件目录是不是也全是 0 权限位，有没有设置「禁止执行」（noexec）。

### 10. 参考材料里的坑，本适配器处理了哪些

| 参考材料记录的坑 | 本适配器 | 计划 |
|---|---|---|
| SDK 调用不报错，不等于送到了：遇到不支持的内容，SDK 只警告，返回空结果 | 没处理，一律当成功 | 第 1 步：返回空结果就算「没成功」，告诉 AI |
| 已读、投票、点赞、编辑这些「控制事件」也走消息通道，不能当成用户说的话 | 全部丢弃（安全，但信息丢了） | 第 4 步改成可读文字注入，不伪装成用户发言 |
| 入站可能重复 | 适配器没去重 | MaiBot 自己会按消息编号去重（已在源码确认），够用 |
| 撤回点赞要用当时返回的点赞对象；编辑、撤回要用发送时返回的原消息，重启后找不回 | 没有句柄缓存 | 按任务书设计缓存，找不到时降级并告诉 AI |
| 大消息：参考实现超过 750KB 就明确丢弃并告警 | 直接塞进连接，超限会断线、侧车重启 | 第 1 步加大小检查 |
| SDK 内部会自动重试，关不掉，不能保证「只发一次」 | 未说明 | 写进说明；我们这层不再额外重试 |
| 免费版共享号码池：只能发给已登记的号码；不能建群 | README 已写 | 不变 |
| Markdown 在 iMessage 上可能退化成纯文字 | 没用 Markdown | 第 2 步按「待测」处理 |
| 特效只能套在文字、Markdown、附件上；投票不能被回复、点赞、撤回 | — | 工具说明里写明 |
| 「标已读」会把整个对话标成已读 | — | 符合我们的用法 |
| 普通消息只能在约 2 分钟内撤回 | — | 写进撤回工具的说明 |
| 发语音要 m4a 格式，否则需要 ffmpeg，镜像里没有 | 没涉及 | 「语音发送预留」时注明：TTS 要输出 m4a，或另配 ffmpeg |
| 用 `node npm-cli.js` 代替 npm 脚本；TypeScript 用 5.9.3 | 没做 | 第 1 步（fnOS） |
| 依赖锁精确版本 | 没锁（`^8.2.1`） | 第 1 步 |
| 需要 Node 22 以上 | nodeenv 会装最新的长期支持版，满足 | 加一个版本检查 |
| 遥测（向 Photon 上报运行数据） | SDK 默认关闭，已确认 | 不用动 |

### 做不了（Photon 不提供，或不在范围内）
- **对方正在输入**：Photon 不送这个状态
- **对方编辑或撤回了自己的消息、对方取消了点赞**：Photon 底层收到了，但 spectrum-ts 不往外转（参考材料和源码一致）

### 现有的其他 bug（顺带记录，后面会修或避开）
- 手动 `/imessage_reconnect` 时，监控程序可能**同时**自动重启一次，变成重启两次

- 对方的昵称显示成手机号

## 七、请本地会话在树莓派上先查的几件事（可选，但能少走弯路）

这些云端做不了。交给本地会话通过 SSH 执行即可（容器名按实际情况替换，官方默认是 `maim-bot-core`）：

```sh
# 1) 数据盘挂载方式（看有没有 noexec）
mount | grep vol1

# 2) 容器里，插件目录能不能执行程序（会建一个临时测试文件，最后删掉）
docker exec maim-bot-core sh -c 'cp /bin/true /MaiMBot/plugins/_x_test && /MaiMBot/plugins/_x_test; echo exit=$?; ls -l /MaiMBot/plugins/_x_test; rm -f /MaiMBot/plugins/_x_test'

# 3) 镜像里实际的插件 SDK 和 MaiBot 版本
docker exec maim-bot-core python -c "import maibot_sdk; print(maibot_sdk.__version__)"
docker image ls | grep maibot
```

`exit=0` 就说明能执行，Node 可以不搬家。`exit=126` 或 Permission denied，就说明必须用第 9 题里的办法。
