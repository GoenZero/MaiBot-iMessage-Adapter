## 二、做了什么

### 基础（第一阶段）

- **传话层重做**：Python 和 Node 侧车之间改用标准输入输出，一行一个 JSON，不占端口。附件走本机临时文件。
- **发送有回执**：侧车真正发出后才告诉 MaiBot 成功，并交还 iMessage 消息编号。失败会如实报告。
- **不再整条丢消息**：回复引用、文字加图片、多张图片、名片、语音、文件、链接、投票、卡片，都会交给 AI；处理不了的内容给一个占位标签。
- **侧车打包随仓库提交**（`sidecar/dist/sidecar.mjs`）：树莓派上不用 `npm install`，也不用编译。
- **自动重启不放弃**：间隔逐渐拉长，最长 5 分钟；只有 Photon 认证失败才停。
- **图片**：HEIC 转 JPEG 并摆正方向；大图缩小；带透明的图片保持 PNG。
- **能力注册表和 WebUI 开关**：每项能力都能单独关掉，关掉后 AI 看不到对应工具，能力说明里也不会提到它。
- **让 AI 知道自己能做什么**：在 iMessage 聊天里，规划器请求前会插入一段 260 字以内的能力说明。这段说明不会进入记忆。
- 正在输入、自动已读、引用回复三档（auto / always / off）、Markdown 显示、上报机器人号码、读取文本文件。

### AI 能用的 iMessage 工具（共 8 个）

| 工具 | 作用 |
|---|---|
| `imessage_react` | 点赞回应（Tapback），也能撤回自己点的 |
| `imessage_edit` | 修改自己 15 分钟内发的文字消息 |
| `imessage_unsend` | 撤回自己 2 分钟内发的消息 |
| `imessage_send_effect` | 发带气泡特效或屏幕特效的消息（13 种） |
| `imessage_poll` | 发起投票（2–12 个选项） |
| `imessage_background` | 设置或清除聊天背景 |
| `imessage_share_contact` | 「共享名字与照片」 |
| `imessage_place_sticker` | 从 MaiBot 表情包库挑一张，当贴纸贴在对方的消息上 |

另外，AI 的一段回复如果只有一个链接，会以链接预览卡片的形式发出。

### 告诉 AI 对方做了什么

- 对方点赞或取消点赞、在投票里选了选项、读了消息、编辑或撤回消息：以 `<imessage_event>` 系统通知的形式写进 AI 的上下文，不叫醒 AI，也不会被当成对方说的话。
- 对方发起的投票、带的气泡特效、屏幕特效和 iOS 18 文字效果（写明是正文里哪几个字）、贴纸（交给 MaiBot 的表情包系统识别）、贴在某条消息上的贴纸。
- 语音：打开「语音转文字」后，用 MaiBot 的语音识别转成文字；关闭或识别失败时，AI 会得体地请对方打字。

### 稳定性（外部审查返修）

- 附件下载卡住时会放弃，不会挡住后面的消息。
- 同一个对话的消息和动作按顺序执行。
- 侧车崩溃、输出乱码、不读输入、长时间连不上时都能恢复。
- 日志里的 Photon 密钥会被遮住，改过密钥后旧密钥也照样遮住。
- 临时文件在各种失败、取消情况下都会删掉。

## 四、做不到或有意没做的

| 内容 | 原因 |
|---|---|
| AI 发 iOS 18 文字效果（摇晃、爆发等） | spectrum-ts 没开放发送，需要再加一处打包修补。按「稳定优先」没做；工具说明里写明了发不了，AI 会如实说 |
| 单独发一张贴纸 | Photon 只支持把贴纸贴在某条消息上；AI 单独发表情包时是普通图片 |
| AI 发语音 | 只做了预留，`voice_send` 永远视为未配置 |
| 群聊 | Photon 免费版是共享号码，只做一对一私聊 |
| 「共享名字与照片」用自定义名字和头像 | 名字和头像来自 Photon 账号的设置，插件改不了 |
| 看出贴纸来自哪个 App | 传过来的只是一张图片 |
| 入站队列上限（审查第 7 条） | 加上限就意味着队列满了要丢消息，和「不丢消息」的原则冲突；一对一私聊不会积压 |
| AI 第一眼漏看文字效果标签 | 标签已经交给 AI，是模型注意力的问题，提醒一下它就能说对；不再为此改动 |

## 五、部署与回滚

- **更新**：在插件目录执行 `git pull origin feature/photon-capabilities`，然后重启 MaiBot。
- **只关掉某个功能**：在 WebUI 里关掉对应开关即可，不用动代码。
- **回到外部审查返修之前（第三阶段交付版）**：`git checkout d2b5b69`，然后重启 MaiBot。
- **回到第三阶段之前**：`git checkout e79d446`，然后重启 MaiBot。
- **回到改造前的旧版（0.1.5，main 分支现状）**：先备份 `config.toml`，再执行 `git checkout main`，然后重启 MaiBot。旧版的配置结构是 1.0.0，项目 ID 和密钥应该会保留，但新开关会失效。

## 六、合并到 main 前还剩的步骤

**前提**：使用者确认日常使用没问题，并明确说「可以合并了」。没有这句话不要做。

1. **处理日常使用中发现的问题**：先在 `feature/photon-capabilities` 上修好，云端测试全部通过，并请使用者在真机上确认。
2. **定版**：`CHANGELOG.md` 里「## [0.2.0] - 未发布」改成实际日期；`config.py` 的 `PLUGIN_VERSION` 和 `_manifest.json` 的版本号确认是 0.2.0（现在已经是）。
3. **合并**：把 `feature/photon-capabilities` 合并进 `main`，用普通合并提交，不要变基或强推。合并后推送 `main`。
4. **打标签**：`git tag v0.2.0`，然后推送这个标签。
5. **部署切换**：使用者的插件目录切回 `main`（`git checkout main && git pull`），重启 MaiBot，发 `/imessage_status` 确认「✅ 已连接」。
6. **收尾**：在本文第一节把状态改成「已合并」，并写上合并日期。

上游原作者的仓库（mayan613/MaiBot-iMessage-Adapter）要不要提 PR，由使用者另外决定。

## 七、给以后接手的 AI

### 规矩

- **和使用者说话一律用中文、说白话**：使用者不写代码，也看不懂长段英文。
- **Photon 项目密钥**不能读取、打印、写进日志或提交。只能通过 WebUI 或配置文件填写。
- 修改 MaiBot 本体或 Docker 配置、删除文件、重启容器、改系统设置，都要先说明并征得同意。
- 保留 GPL-3.0 许可证和原作者署名；打包产物要附带第三方许可证。
- 提交和 PR 里不要写模型名称；没有被要求时不要开 PR。
- 稳定优先：不加高风险的新功能。
- 写进「对方消息」里的方括号标签只写中性描述，不写给 AI 的指令，否则会被 MaiBot 的记忆模块当成对方的原话。给 AI 的指令写在能力说明（`core/capabilities.py`）或工具说明（`tools.py`）里。能力说明要控制在 260 字以内。

### 代码在哪

仓库结构见 [REVIEW-BRIEF.md](REVIEW-BRIEF.md) 第二节。三个最容易出错的地方：

- `sidecar/build-config.mjs` 在打包时修补第三方代码，一共 5 处：
  - `advanced-imessage` 的 gRPC 依赖检查（打包后会误报）。
  - `@spectrum-ts/imessage` 的 4 处（在 `patchImessageSource` 里）：没有标题的投票、转发编辑/撤回/取消点赞/贴纸、转发对方发起的投票、贴贴纸入口。

  `build.mjs` 会检查每处修补都正好生效一次，找不到要改的代码时打包直接失败。升级 spectrum-ts 时，这里一定要重新核对。
- 改了 `sidecar/src` 之后必须重新打包，并把 `sidecar/dist/sidecar.mjs` 一起提交；`npm run check` 会检查打包文件和源码是否一致。
- `core/effects.py` 里的特效中文名已经和 iPhone 真机核对过（例如文字效果「爆发」、屏幕特效「回声」），不要凭印象改。
